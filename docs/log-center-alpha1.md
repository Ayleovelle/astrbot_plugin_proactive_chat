# 主动消息 · 详细日志中心 alpha1 测试说明

> 本文保留原 alpha1 测试包的历史说明。当前 alpha2 的发送语义、控制台脱敏、输入核验与最新测试范围见 [alpha2 说明](log-center-alpha2.md)。

版本：v1.2.6+logcenter.alpha1  
基于：Pancakes-Labs/astrbot_plugin_proactive_chat 的 635fc18eeb84e3c7b58661425359244552286835（v1.2.6）  
性质：个人本地测试包，不是上游正式版本；没有推送仓库或创建 PR。

## 这版能看到什么

WebUI 左侧新增「日志中心」。等级和事件类型分开：DEBUG / INFO / WARNING / ERROR / CRITICAL；决策、生成、发送、状态、运行。

正常任务也会详细记录：
- 每轮任务的关联 ID，定时或手动入口，结束与实际耗时
- 会话配置是否存在、是否启用、是否命中免打扰，各项实际结果与期望值
- 当前未回复次数、配置上限、是否允许继续，以及跳过的明确原因
- 上下文来源、历史条数、平台流水读取/注入条数、提供者选择路径、钩子结论
- 生成结果的文本长度、组件数量、耗时；不记录生成正文
- 发送路径、真实返回值的语义、异常与实际发生的回退顺序
- 存档回读是否确认、未回复计数前后值、下次间隔候选范围、随机选择值、下次触发时间

点击任意日志可看结构化详情、源文件/函数/行号；点击「查看本次任务完整链路」可以按关联 ID 串起过程。正常列表也直接显示关键实际值，无需只看模糊的开始/结束标记。

支持最低等级、事件类型、完整会话 ID、完整关联 ID、开始/结束时间筛选；每页 50 条，最新在前。自动刷新默认关闭，开启后每 5 秒刷新第一页，翻页或隐藏标签页时暂停自动刷新。

## 发送状态请这样理解

- explicit_success：该接口明确返回 True，不代表终端已收到或已读
- explicit_failure：该接口明确返回 False
- returned_without_receipt / unknown_no_receipt：调用返回但没有送达回执，实际送达未知
- unknown_after_exception：异常后实际状态未知，可能已经投递；原有回退路径可能造成重复投递
- flow_returned_true：插件发送流程整体返回 True，应结合该任务的接口记录一起看

本测试包增加观测，不重新定义上游发送算法。尤其上游对某些 None 返回、部分分段成功的记账方式仍然保留。不能只凭流程 True 判定所有分段或终端都已收到。

## 隐私与错误信息

日志中心不保存消息正文、提示词、模型完整响应、动态日志参数、原始异常字符串、局部变量或 traceback 源代码行。不会接管 AstrBot 全局 logger 或收集其他插件的日志。

现有运行日志通过插件自己的日志门面保留等级与源代码中的静态文案，动态插值显示「[已隐藏]」。原有 AstrBot 控制台输出保持原来文案；本日志中心的隐私措施不等于清理了 AstrBot 本身已有的控制台日志。

错误详情保留真实异常类型、调用帧的文件/函数/行号、因果链，以及安全的系统错误码 errno（如果有）。原始错误消息即使看似普通，也可能包含 prompt、密钥或远端响应，因此默认隐藏。异常最多保留 64 个调用帧、5 层因果链；过大时明确标注截断，而不是悄悄伪造完整堆栈。

「导出筛选诊断 JSON」在浏览器本地下载当前筛选范围的记录，最多 1000 条；达到上限会标注截断。诊断文件仍含会话标识，分享前请检查。没有自动上传日志到第三方。插件原有的模型调用、通知与遥测按原来的配置运行，不属于此日志中心新增的上传。

## 安装前

1. 建议先在独立的测试 AstrBot 实例安装，或只给测试会话启用主动消息。
2. 备份现有插件文件、插件配置和插件数据目录。不要删除原来的 session_data.json。
3. 本包要求沿用上游的 AstrBot >=4.24.0 与 requirements.txt 依赖；没有新增第三方 Python 运行依赖，SQLite 来自 Python 标准库。
4. Web 管理端建议保留 127.0.0.1 监听并设置强密码。若从局域网访问，应先设置密码并重载插件，不要把无密码管理端暴露到公网。

## 安装测试包

优先使用你当前 AstrBot 已支持的本地 ZIP 安装/更新入口，选择附带的 astrbot_plugin_proactive_chat-v1.2.6-logcenter-alpha1.zip。

如果当前版本没有这个入口：先停用插件或停止 AstrBot，再解压 ZIP，把其中 astrbot_plugin_proactive_chat 目录的内容覆盖到原插件目录；保留原插件名，不要额外装成第二份。随后启动/重载插件。具体插件根目录取决于你的 AstrBot 部署方式。

打开已有 Web 管理端地址，强制刷新浏览器缓存。确认版本显示 v1.2.6+logcenter.alpha1，左侧出现「日志中心」。不要把说明文件或外层目录当成插件单独安装。

此包的前端 JSX 已预编译为 JS；仍沿用上游 React/MUI 等 CDN 加载方式，因此访问 WebUI 需要原有 CDN 可用。

## 建议按顺序测试

1. 进入日志中心
   - 新安装只从现在开始记录，不补录旧日志
   - 默认 INFO+；正常显示运行记录，不要求一定出现 ERROR
2. 正常成功任务
   - 在专门的测试会话手动触发一次，或等待测试会话原有定时任务
   - 注意：这一步会实际调用模型，并可能向该测试会话发送消息
   - 用同一关联 ID 检查：条件 → 次数上限 → 上下文/模型 → 生成 → 发送 → 存档 → 计数 → 下次调度 → 结束
   - 核对次数与下一次触发时间是否与任务管理页一致
3. 正常跳过
   - 给测试会话设置免打扰时段或让未回复次数达到测试上限
   - 检查跳过原因和实际阈值；不应出现成功发送计数
   - 完成后恢复测试会话原配置
4. DEBUG
   - 在配置管理 → 本地日志中心，开启「记录 DEBUG 日志」，保存并重载插件
   - 筛选最低等级为 DEBUG，确认出现额外细节；验证正文和密钥仍不出现
   - 排查结束后建议关闭 DEBUG 并重载
5. 错误与发送未知
   - 仅在测试实例观察自然出现的错误；不要故意破坏正式环境凭据或网络
   - 检查 ERROR/WARNING 的类型、阶段、调用帧、回退路径和同链路前后记录
   - None 返回不得显示为已读或确定送达
6. 页面交互
   - 测试筛选、下一页/上一页、查看详情、关闭再打开、查看任务链路、重置筛选
   - 验证空结果提示、登录过期提示、网络恢复后的刷新
   - 开启自动刷新，翻到第二页后确认不会被持续拉回第一页
7. 导出与持久化
   - 对一个关联 ID 导出 JSON，检查记录数量、时间、字段与页面一致
   - 检查没有消息正文、提示词、凭据、局部变量；分享前再检查会话 ID
   - 重载插件后确认此前日志还在，且没有重复采集或重复启动的写入线程

## 保存与容量

日志文件：插件专属数据目录下的 log_center.sqlite3，与 session_data.json 分开。

默认保留 7 天、最多 10000 条，先达到哪个上限就清理哪个。可配置 1–30 天、100–50000 条；主数据库额外限制约 32 MiB，不包含短期 SQLite 回滚日志。写入队列上限 1000 条。队列满、磁盘满或写入失败时不阻断主动消息，页面会显示丢弃数或存储错误。

保留天数、容量、DEBUG 和启用开关在重载插件后生效。降低保留上限会自动清理更早记录，不能在页面恢复；测试前如需保留旧日志，请先导出。

## 验证结果与边界

已完成：25 项隔离 Python 测试，包含正常成功/跳过/失败、并发关联 ID、真实发送 helper 的 None/False/异常回退、鉴权、分页与 SQL 参数、重启持久化、时间/条数保留、丢弃与存储失败、隐私、非有限数值/时间拒绝。Python 编译和关键静态检查通过；前端预编译通过。

React DOM 交互检查通过：首屏、分页/返回、详情关闭与重开、关联链路、跨页导出、筛选与空结果、自动刷新开关、读取失败清除旧数据与恢复；没有 React 运行错误。真实浏览器未验：远程云浏览器不能访问容器 localhost，隔离 Chromium 也被运行环境的 socket 限制阻止启动，不能把 DOM 测试当成视觉验收。实际 AstrBot 平台 SDK、真实模型/消息平台、移动端视觉与 CDN 兼容性尚未实机验证。本包适合你先小范围测试，不应视为生产环境验收完成。

本次还修复了一处现有鉴权边界：设置密码后，固定的 no-auth 哨兵不能再充当有效 Bearer token。

可在独立命令行进程运行随包隔离测试：python -m unittest discover -s tests -v。需要 FastAPI 与 httpx；测试会替换进程内 AstrBot 模块为假对象，请勿在正在运行的 AstrBot 进程内直接 import 测试文件。

## 回退

先停用插件或停止 AstrBot，再用备份的插件文件覆盖回原版本；必要时恢复配置备份。保留原会话数据。新增 SQLite 日志文件可留在数据目录中，旧版不会读取它。不要卸载后连同插件数据一起删除，以免丢失原有会话状态。

反馈时建议提供：AstrBot 版本、平台适配器、测试动作、预期/实际行为、单次任务的关联 ID，以及检查过隐私后的诊断 JSON。
